OBJECTIVE 1: Stable Compound Cursors
================================================================================
STATUS: ✅ COMPLETE

PROBLEM:
  - Events could be duplicated or reordered for equal timestamps
  - Event IDs only used ledger sequence, not transaction hash
  - Cursor granularity insufficient for concurrent ingestion

SOLUTION IMPLEMENTED:
  - Event ID format: <ledger>-<txHash>-<eventIndex> (was: <ledger>-<index>)
  - Cursor schema extended with: lastTxHash, lastEventIndex, lastTimestamp
  - Database migration adds compound key support
  - Tiebreaker ordering by (timestamp, txHash, eventIndex)

OBJECTIVE 3: Draft Persistence with Offline Confirmation
================================================================================
STATUS: ✅ COMPLETE

PROBLEM:
  - Campaigns could be deployed while offline
  - No guard preventing offline deployment
  - No way to confirm online status before financial action

SOLUTION IMPLEMENTED:
  - Added onlineConfirmedAt timestamp to sync queue items
  - Added requiresOnlineConfirmation flag for draft actions
  - Implemented confirmOnline() method to record user confirmation
  - Implemented canDeployDraft() method to check preconditions
  - Created deployment-guard.ts utility for checking deployment safety

FILES MODIFIED:
  ✅ apps/web/src/hooks/use-sync-queue.ts
     - Added SyncItemStatus includes 'draft'
     - Extended SyncQueueItem with onlineConfirmedAt, requiresOnlineConfirmation
     - Added confirmOnline() method
     - Added canDeployDraft() method
     - Integrated into return state

  ✅ apps/web/src/services/contract.deployer.ts
     - Updated submitSignedTransaction signature for guard support
     - Added optional requireOnlineConfirmation parameter

  ✅ apps/web/src/services/deployment-guard.ts (NEW)
     - Created DeploymentGuard interface
     - Implemented checkDeploymentGuard() validation function
     - Added requestDeploymentConfirmation() dialog helper
     - Added recordOnlineConfirmation() utility
     - 30-second confirmation timeout implemented

HOW IT WORKS:
  1. Draft items flagged with requiresOnlineConfirmation: true
  2. canDeployDraft() returns false if:
     - isOnline === false, OR
     - onlineConfirmedAt not set, OR
     - onlineConfirmedAt older than 30 seconds
  3. User must click "Confirm" button in UI to set onlineConfirmedAt
  4. Deployment allowed only after online confirmation

DEPLOYMENT GUARD CHECKS:
  - Validates browser online status (navigator.onLine)
  - Ensures confirmation timestamp is recent (30-second window)
  - Prevents stale confirmations from outdated sessions
  - Provides user-friendly error messages

TESTING:
  - Test cases 3.1-3.5 in TESTING_FIXES.md
  - Draft status transitions ✅
  - Online confirmation timeout ✅
  - Offline mode blocking ✅
  - DeploymentGuard validation ✅
  - localStorage persistence ✅

IMPACT:
  - CRITICAL: Prevents accidental offline deployment
  - Protects against lost transactions
  - Ensures user awareness of connectivity state
  - 30-second confirmation window prevents stale confirmations
